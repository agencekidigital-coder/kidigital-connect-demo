# Stripe Connect — bêta Cloudflare, phase configuration

Mode test uniquement : les comptes Stripe de test sont isolés dans naitea_stripe_test_accounts, accès service_role uniquement. Le Worker vérifie l'utilisateur auprès de Supabase, crée un compte Accounts v2 merchant avec Dashboard complet et responsabilités Stripe uniquement au clic explicite, génère un lien d'onboarding v2 à usage unique, puis vérifie la configuration et la capacité card_payments active auprès de Stripe. Version API épinglée à 2026-11-18.endive. Cette vérification indique l'aptitude au paiement par carte, pas une garantie de versement. Le passage à v2 utilise une nouvelle clé d'idempotence stable pour ne pas rejouer l'ancienne erreur v1. Un retour n'est pas une preuve d'activation. L'URL de retour/rafraîchissement est /compte#stripeTestPanel ; la professionnelle peut relancer le lien. Aucun paiement n'est activé.

Configuration Cloudflare preview : NAITEA_STRIPE_TEST_ENABLED=true et secret NAITEA_STRIPE_TEST_SECRET_KEY (sk_test_ uniquement). Ne jamais mettre la clé dans Git, dans une variable publique ni dans le navigateur. Tester l'onboarding depuis Mon compte. L'ancienne table naitea_stripe_accounts n'est pas modifiée. Si la professionnelle souhaite connecter un compte Standard existant, étudier le parcours de rattachement pris en charge par Accounts v2 avant de l'activer.

Phase suivante : réservation temporaire atomique, prix serveur et compte connecté vérifié, Stripe Checkout direct charge sans application_fee_amount ; webhook Connect signé sur corps brut, vérification account/id/montant/devise/mode, idempotence et expiration/libération des places. Paiements sur place restent disponibles. Ne pas confirmer de réservation payante sur simple retour navigateur. Aucun secret webhook ni charge réelle dans cette phase.

Compatibilité Endive : le champ `use_case.account_onboarding.configurations` n'est plus accepté (erreur Stripe `invalid_fields`, confirmée en bêta). La configuration merchant reste définie à la création du compte ; les liens d'inscription utilisent uniquement collection_options, refresh_url et return_url. Le compte déjà associé est conservé.
