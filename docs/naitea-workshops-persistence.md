# Naïtea – ateliers privés, première étape (25/11/2026)
Branche de travail indépendante, **flag NAITEA_WORKSHOPS_ENABLED=false**. Ne pas activer avant build et tests réels. Aucun import du stockage de démonstration.
- Le 25/11, un test transactionnel Supabase sur deux identités distinctes a validé création et modification par propriétaire, absence de visibilité/modification/suppression croisée, rejet de création sous un autre propriétaire. Toutes les écritures ont été annulées; 0 atelier après test. Identités simulées au niveau SQL, pas deux sessions HTTP.
- /mes-ateliers est une page de test séparée; /api/workshops vérifie le jeton chez Supabase Auth puis applique le filtre propriétaire et transmet le jeton à la base avec RLS. Création et modification de brouillons seulement. Pas de suppression, publication, réservation, paiement ou synchronisation de la démo. Les droits SQL directs de la table restent plus larges que cette interface; la publication directe et le périmètre des droits doivent être revus avant ouverture générale.
- Données: titre, description, date/heure facultative, capacité, prix en centimes. Liste limitée à 100; pagination et gestion de concurrence à compléter. L'heure est celle de l'appareil au moment de la saisie; choix de fuseau à traiter avant le lancement.
- Tests à exécuter: node --test tests/workshops-persistence.test.mjs; npm test; npm run build:cloudflare; npx wrangler deploy --dry-run. Puis déploiement bêta isolé et activation explicitement limitée à cette version, test de persistance A/B via sessions réelles, reprise après rechargement et sur mobile. Ne pas activer l'API publique de réservations/paiements.
